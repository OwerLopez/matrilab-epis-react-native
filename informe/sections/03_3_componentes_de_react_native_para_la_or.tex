\phantomsection\addcontentsline{toc}{subsection}{3.1 Cómo dibuja React Native una interfaz}
\colabtitle{3.1 Cómo dibuja React Native una interfaz}

En React Native la interfaz se describe con componentes de React, pero lo que aparece en pantalla no es HTML: el renderizador \textbf{Fabric} traduce cada componente del núcleo a una vista nativa del sistema operativo [2], [13]. Las posiciones y tamaños se calculan con \textbf{Yoga}, un motor de layout multiplataforma que implementa Flexbox [15]. \phantomsection\addcontentsline{toc}{subsection}{3.2 Flexbox en React Native}
\colabtitle{3.2 Flexbox en React Native}

Toda la organización espacial se hace con Flexbox. Un contenedor define un \textbf{eje principal} (\texttt{flex\allowbreak{}Direction}) y distribuye a sus hijos a lo largo de él (\texttt{justify\allowbreak{}Content}) y del eje transversal (\texttt{align\allowbreak{}Items}). La documentación oficial advierte que, aunque el modelo es el de CSS, \textbf{los valores por defecto cambian} [1]: \texttt{flex\allowbreak{}Direction} vale \texttt{column} (en la web vale \texttt{row}), \texttt{align\allowbreak{}Content} vale \texttt{flex-start}, \texttt{flex\allowbreak{}Shrink} vale 0 y \texttt{flex} acepta un solo número. \phantomsection\addcontentsline{toc}{subsection}{3.3 Contenedores de organización}
\colabtitle{3.3 Contenedores de organización}

\begin{itemize}[label=\textcolor{unsared}{\textbullet}, leftmargin=*]
    \item \textbf{View.} Es el bloque de construcción de toda pantalla. MatriLab no usa ninguna librería de componentes visuales: tarjetas, botones, chips, insignias y barras de progreso se construyeron sobre View, Text y Pressable.
    \item \textbf{SafeAreaView.} Evita que el contenido quede bajo la barra de estado o la muesca. La documentación marca el del núcleo como obsoleto y recomienda \texttt{react-native-safe-area-context} [16], que es el que usa la aplicación.
    \item \textbf{ScrollView.} Contenedor desplazable que monta todos sus hijos a la vez [3]. Se usa en pantallas de contenido acotado (panel del estudiante, detalle, pase, horario, configuración, perfil) y en forma horizontal para la fila de filtros del catálogo.
    \item \textbf{KeyboardAvoidingView.} Ajusta el espacio cuando aparece el teclado [8]; su comportamiento difiere entre Android e iOS, por eso se configura según la plataforma (ver Figura \ref{fig:i01}, panel d).
    \item \textbf{Modal.} Presenta contenido sobre la pantalla actual [9]. Con fondo transparente se construyó una hoja inferior para editar los datos de un laboratorio (Figura \ref{fig:i10}, panel c).
\end{itemize}

\phantomsection\addcontentsline{toc}{subsection}{3.5 Posicionamiento, dimensiones y adaptación}
\colabtitle{3.5 Posicionamiento, dimensiones y adaptación}

\begin{itemize}[label=\textcolor{unsared}{\textbullet}, leftmargin=*]
    \item \textbf{Posición absoluta.} Saca a un elemento del flujo y lo ubica respecto de su contenedor; \texttt{Style\allowbreak{}Sheet.\allowbreak{}absolute\allowbreak{}Fill} lo cubre por completo, como la vista de cámara del escáner.
    \item \textbf{Porcentajes.} Ancho y alto aceptan porcentajes del contenedor [12]; así se dibuja el relleno de la barra de ocupación.
    \item \textbf{useWindowDimensions} devuelve el ancho y alto de la ventana y se actualiza al rotar [10]. Con él se calculan el ancho de cada día del horario, el tamaño del QR y las columnas de la lista de laboratorios.
    \item \textbf{Platform} permite pequeñas diferencias por sistema [11]; \textbf{StyleSheet} agrupa los estilos y ofrece la línea más fina que puede dibujar la pantalla, usada en bordes y separadores [6].
    \item \textbf{useColorScheme} informa si el sistema está en modo claro u oscuro y define la paleta de toda la aplicación.
\end{itemize}

\phantomsection\addcontentsline{toc}{subsection}{3.7 Navegación nativa}
\colabtitle{3.7 Navegación nativa}

React Native no incluye un navegador en su núcleo; se usó \textbf{React Navigation} [20], [21]. La pila nativa delega en los componentes del sistema (fragmentos en Android y \texttt{UINavigation\allowbreak{}Controller} en iOS), por lo que las transiciones y el gesto de volver son los del sistema. El detalle del grupo se presenta como hoja modal y cada rol tiene su barra de pestañas inferior, cuyos iconos cambian entre la versión rellena y la de contorno según la pestaña activa.
